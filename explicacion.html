Lista de Tareas, explicada línea por línea

Este proyecto usa JavaScript puro: sin React, sin jQuery, sin instalar nada. Solo tres archivos y un navegador. Al terminar vas a entender de verdad cómo una aplicación guarda información, la muestra en pantalla y reacciona a lo que hace el usuario.

Lo que vas a aprender acá

  • Cómo conectar HTML, CSS y JavaScript entre sí.
  • Cómo guardar datos en un array de objetos y mantenerlos sincronizados con la pantalla.
  • Los métodos que más se usan en el trabajo real: map, filter, find, some.
  • Cómo escuchar eventos con delegación (la técnica que usan las apps grandes).
  • Cómo hacer que los datos sobrevivan al cerrar el navegador con localStorage.
Cómo leer esta guía

Tené la app abierta en otra pestaña. Después de cada sección, probá lo que acabás de leer: cambiá un valor, borrá una línea y mirá qué se rompe. Romper cosas a propósito es la forma más rápida de entender para qué servían.

Cómo funciona todo, en 1 minuto

Antes de mirar una sola línea de código, quedate con esta idea, porque es la columna vertebral del proyecto entero:

  1. Hay una lista en la memoria. Una variable llamada tareas guarda todas las tareas como objetos.
  2. La pantalla es un reflejo de esa lista. Una función llamada dibujar() lee tareas y genera el HTML.
  3. El usuario nunca toca la pantalla directamente. Cuando hace clic, cambiamos la lista y volvemos a llamar a dibujar().
  4. Después de cada cambio, guardamos. La lista se copia a localStorage para que siga ahí mañana.
La regla de oro

Nunca modificamos el HTML "a mano" para tachar una tarea. Cambiamos el dato (hecha: true) y dejamos que dibujar() se encargue del resto. Esta idea se llama "la interfaz es una función del estado" y es exactamente el principio sobre el que están construidos React, Vue y Svelte. Si lo entendés acá, ya entendiste la mitad de esos frameworks.

1 · El HTML: el esqueleto

El HTML no hace nada por sí solo: solo define qué elementos existen y les pone un nombre para que JavaScript pueda encontrarlos después. Fijate en los id: cada uno de ellos aparece más adelante en el JavaScript.

La cabecera del documento

index.html
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Lista de Tareas | Mini-Proyectos JS</title>
  <link rel="stylesheet" href="style.css">
</head>
  • <!DOCTYPE html>Le dice al navegador que use las reglas modernas de HTML5. Sin esto, algunos navegadores entran en "modo raro" y el diseño se rompe.
  • lang="es"Indica que la página está en español. Ayuda al buscador de Google y al lector de pantalla de una persona no vidente.
  • charset="UTF-8"Sin esta línea, los acentos y las ñ se ven como Ã±. Es la causa número uno de textos rotos.
  • viewportHace que la página se adapte al ancho del celular en vez de mostrarse diminuta.
  • <link rel="stylesheet">Conecta el archivo style.css. Sin esta línea la app funciona igual, pero se ve como un documento de 1998.

El formulario para agregar tareas

index.html
<form class="formulario" id="formulario">
  <input
    type="text"
    id="entrada"
    class="formulario__input"
    placeholder="¿Qué tenés que hacer hoy?"
    autocomplete="off"
    maxlength="120">
  <button type="submit" class="formulario__boton">+</button>

  • <form>Usamos un formulario de verdad, no un simple <div>. Así el usuario puede presionar Enter para agregar la tarea y funciona gratis, sin código extra.
  • id="formulario"El nombre con el que JavaScript va a encontrar este elemento.
  • placeholderEl texto gris que se ve cuando el campo está vacío. Desaparece al escribir.
  • autocomplete="off"Evita que el navegador muestre sugerencias de otros formularios encima de la app.
  • maxlength="120"Límite de caracteres. Sin esto, alguien pega un texto de 5.000 letras y te rompe el diseño.
  • type="submit"Hace que este botón envíe el formulario. Es lo que dispara el evento submit que vas a ver en el JavaScript.

El <script src="script.js"></script> va al final del body, justo antes de </body>. Si lo ponés en el <head>, el JavaScript se ejecuta antes de que los elementos existan y todos los getElementById devuelven null. Es el error más común de los principiantes.

2 · El CSS: el diseño

No hace falta que entiendas cada propiedad de memoria, pero sí que sepas dónde tocar cuando quieras cambiar algo. Estas son las partes que importan.

Variables de color: cambiá la app entera desde un solo lugar

style.css
:root {
  --fondo:        #0e1116;
  --superficie:   #171b22;
  --texto:        #e6e9ef;
  --acento:       #4f8cff;
  --exito:        #35d399;
  --peligro:      #ff5f6d;
  --radio:        14px;
}
  • :rootSe refiere al documento entero. Lo que definís acá está disponible en todo el archivo.
  • --acento: #4f8cffUna variable CSS. Después se usa así: background: var(--acento).
Un solo valor, cinco cambios

--acento pinta el botón de agregar, el borde del campo cuando lo enfocás, su anillo de luz, el resplandor azul del fondo y el filtro que está activo. Cambiar ese único valor cambia las cinco cosas a la vez.

Sin variables tendrías el mismo color escrito cinco veces en lugares distintos del archivo, y para cambiarlo habría que encontrarlos todos sin olvidarse de ninguno. Eso es lo que quiere decir que un código sea mantenible: que un cambio se haga en un solo lugar.

El truco del box-sizing

style.css
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}

El * significa "todos los elementos". border-box hace que el ancho que le pongas a un elemento incluya su padding y su borde. Sin esto, una caja de 200px con 20px de padding mide en realidad 240px y todo se te desalinea. Es la primera regla que escribe casi cualquier desarrollador front-end.

Cómo se tacha una tarea completada

style.css
.tarea--hecha .tarea__texto {
  color: var(--texto-suave);
  text-decoration: line-through;
}

.tarea--hecha .tarea__check {
  color: #0e1116;
  background: var(--exito);
  border-color: var(--exito);
}

Acá está la conexión entre CSS y JavaScript, y es importante que la veas: JavaScript no cambia colores ni tacha texto. Lo único que hace es agregar o quitar la clase tarea--hecha. El CSS ya tiene escrito de antemano cómo se ve una tarea con esa clase. Separar responsabilidades así hace que ambos archivos queden mucho más simples.

El botón de borrar que aparece al pasar el mouse

style.css
.tarea__borrar { opacity: 0; }

.tarea:hover .tarea__borrar { opacity: 1; }

@media (hover: none) {
  .tarea__borrar { opacity: 1; }
}
  • opacity: 0El botón está ahí, ocupa su lugar, pero es invisible. Mantiene la interfaz limpia.
  • .tarea:hover .tarea__borrar"Cuando el mouse esté sobre la tarea, mostrá su botón de borrar".
  • @media (hover: none)Detecta pantallas táctiles, donde no existe el "pasar el mouse". En celulares el botón siempre se ve. Sin esta regla, la app sería imposible de usar en el teléfono: un detalle que separa un proyecto de práctica de uno profesional.

3 · JavaScript: referencias al HTML

script.js
'use strict';

const formulario   = document.getElementById('formulario');
const entrada      = document.getElementById('entrada');
const lista        = document.getElementById('lista');
const filtros      = document.getElementById('filtros');
const contador     = document.getElementById('contador');
const botonLimpiar = document.getElementById('limpiar');
const vacio        = document.getElementById('vacio');
const aviso        = document.getElementById('aviso');

const CLAVE_GUARDADO = 'mini-proyectos-js:tareas';
  • 'use strict'Activa el modo estricto: JavaScript deja de perdonar errores silenciosamente y te avisa. Por ejemplo, si escribís mal el nombre de una variable, te lo dice en vez de crear una nueva.
  • constCrea una variable que no se va a reasignar. Si escribís const x = 1 y después x = 2, JavaScript te da error. Es una red de seguridad, no una limitación.
  • document.getElementById('entrada')Busca en la página el elemento cuyo id es entrada y te devuelve una referencia a él. A partir de acá, la variable entrada es ese campo de texto.
  • CLAVE_GUARDADOEn MAYÚSCULAS porque es una constante que nunca cambia. Es una convención: cualquier programador que lea tu código entiende de inmediato que ese valor es fijo.
¿Por qué buscar todo al principio?

Buscar un elemento en el documento tiene un costo. Si lo hiciéramos dentro de cada función, el navegador tendría que recorrer la página una y otra vez. Buscándolos una sola vez al inicio el código queda más rápido y más corto: escribís entrada en vez de document.getElementById('entrada') cada vez.

4 · El estado: la única fuente de verdad

script.js
let tareas = cargarTareas();
let filtroActual = 'todas';
  • letA diferencia de const, let sí permite reasignar. Lo usamos porque tareas se reemplaza entera cuando borramos algo.
  • filtroActualGuarda cuál de los tres botones está activo. Puede valer 'todas', 'pendientes' o 'completadas'.

Cada tarea es un objeto con tres propiedades:

forma de una tarea
{
  id: 1723658400000,        // momento exacto en que se creó
  texto: "Comprar pan",     // lo que escribió el usuario
  hecha: false              // ¿está completada?
}

Y tareas es simplemente un array (una lista) de esos objetos:

ejemplo
[
  { id: 1723658400000, texto: "Comprar pan",         hecha: false },
  { id: 1723658300000, texto: "Estudiar JavaScript", hecha: true  }
]
El concepto más importante del proyecto

Todo lo que ves en pantalla sale de este array. Si querés saber por qué la app muestra algo, no mires el HTML: mirá el array. Abrí la consola del navegador (F12) mientras usás la app y escribí tareas. Vas a ver la lista real cambiando en vivo.

5 · Guardar y cargar: que no se pierda nada

script.js
function guardarTareas() {
  try {
    localStorage.setItem(CLAVE_GUARDADO, JSON.stringify(tareas));
  } catch (error) {
    console.warn('No se pudieron guardar las tareas:', error);
  }
}

function cargarTareas() {
  try {
    const guardado = localStorage.getItem(CLAVE_GUARDADO);
    if (!guardado) return [];
    const datos = JSON.parse(guardado);
    return Array.isArray(datos) ? datos : [];
  } catch (error) {
    console.warn('No se pudieron leer las tareas:', error);
    return [];
  }
}
  • localStorageUn pequeño almacén que vive dentro del navegador del usuario. Lo que guardás ahí sigue estando mañana, la semana que viene y después de apagar la computadora.
  • JSON.stringify(tareas)localStorage solo guarda texto. Esto convierte el array en una cadena de texto: '[{"id":172...}]'.
  • JSON.parse(guardado)La operación inversa: convierte ese texto de vuelta en un array de objetos usable.
  • if (!guardado) return []Si es la primera vez que la persona entra, no hay nada guardado. Devolvemos un array vacío en vez de dejar que el programa falle.
  • Array.isArray(datos) ? datos : []Un operador ternario: ¿es un array? entonces usalo, si no usá uno vacío. Nos protege de datos corruptos.
  • try / catch"Intentá esto; si explota, hacé esto otro en vez de romper todo". Algunos navegadores en modo incógnito bloquean localStorage: con try/catch la app sigue funcionando igual, solo que sin memoria.

6 · Funciones de ayuda

Protegerse del HTML malicioso

script.js
function limpiarTexto(texto) {
  const div = document.createElement('div');
  div.textContent = texto;
  return div.innerHTML;
}

Esta función chiquita hace algo importante. Como más adelante insertamos el texto del usuario usando innerHTML, si alguien escribiera <img src=x onerror=alert(1)> como tarea, el navegador lo ejecutaría como código real. Eso se llama XSS y es una de las vulnerabilidades más comunes de la web.

  • createElement('div')Crea un div en la memoria, sin agregarlo a la página.
  • div.textContent = textotextContent trata todo como texto plano: no interpreta etiquetas.
  • return div.innerHTMLAl leerlo de vuelta como HTML, los caracteres peligrosos ya vienen convertidos en &lt; y &gt;. Ahora se muestran como texto, no se ejecutan.

El aviso emergente

script.js
let temporizadorAviso;

function mostrarAviso(mensaje) {
  aviso.textContent = mensaje;
  aviso.classList.add('aviso--visible');
  clearTimeout(temporizadorAviso);
  temporizadorAviso = setTimeout(() => {
    aviso.classList.remove('aviso--visible');
  }, 2000);
}
  • classList.add(...)Agrega una clase CSS al elemento. El CSS se encarga de la animación de entrada.
  • clearTimeout(...)Cancela el reloj anterior. Sin esta línea, si borrás dos tareas seguidas rápido, el primer temporizador escondería el segundo aviso demasiado pronto. Es un detalle chico que casi nadie hace y que se nota.
  • setTimeout(fn, 2000)Ejecutá esta función dentro de 2000 milisegundos (2 segundos).
  • () => { ... }Una función flecha: una forma corta de escribir function() { ... }.

Filtrar lo que se muestra

script.js
function tareasVisibles() {
  if (filtroActual === 'pendientes')  return tareas.filter(t => !t.hecha);
  if (filtroActual === 'completadas') return tareas.filter(t =>  t.hecha);
  return tareas;
}
  • .filter(...)Recorre el array y devuelve un array nuevo solo con los que cumplen la condición. El original queda intacto: por eso los filtros no borran nada.
  • t => !t.hecha"Para cada tarea t, quedátela si hecha es falso". El ! significa "no".
  • ===Compara valor y tipo. Usá siempre === y no ==: con dos iguales, '1' == 1 da verdadero y eso genera errores rarísimos.

7 · Dibujar la pantalla

Esta es la función más importante del proyecto. Se llama cada vez que algo cambia.

script.js
function dibujar() {
  const visibles = tareasVisibles();

  lista.innerHTML = visibles.map(tarea => `
    <li class="tarea ${tarea.hecha ? 'tarea--hecha' : ''}" data-id="${tarea.id}">
      <button class="tarea__check" data-accion="alternar"><!-- icono tilde --></button>
      <span class="tarea__texto">${limpiarTexto(tarea.texto)}</span>
      <button class="tarea__borrar" data-accion="borrar"><!-- icono papelera --></button>
    </li>
  `).join('');

  const pendientes = tareas.filter(t => !t.hecha).length;
  contador.textContent =
    pendientes === 1 ? '1 tarea pendiente' : `${pendientes} tareas pendientes`;

  botonLimpiar.style.visibility = tareas.some(t => t.hecha) ? 'visible' : 'hidden';
}
  • .map(tarea => ...)Transforma cada elemento del array en otra cosa. Acá convierte cada objeto tarea en un pedazo de HTML. Si hay 5 tareas, devuelve un array de 5 textos.
  • ` ... `Comillas invertidas: template literals. Permiten escribir texto en varias líneas e insertar valores con ${...}.
  • ${tarea.hecha ? 'tarea--hecha' : ''}Si la tarea está hecha, poné esa clase; si no, no pongas nada. Así es como el CSS sabe cuándo tachar el texto.
  • data-id="${tarea.id}"Guardamos el id dentro del propio HTML. Cuando el usuario haga clic, vamos a leer este atributo para saber a qué tarea se refería.
  • data-accion="alternar"Etiqueta qué hace cada botón. Una sola función de clics va a leer esto y decidir qué ejecutar.
  • .join('')map devuelve un array de textos; join('') los pega todos en un solo texto gigante, sin separador.
  • lista.innerHTML = ...Reemplaza todo el contenido de la lista de una sola vez. Es mucho más rápido que insertar los elementos de a uno, porque el navegador redibuja una vez y no cinco.
  • .lengthLa cantidad de elementos del array. Combinado con filter, es la forma más simple de contar.
  • .some(t => t.hecha)Devuelve verdadero si al menos una tarea está completada. Lo usamos para esconder el botón "Borrar completadas" cuando no hay ninguna.
Lo que hay que entender de esta función

dibujar() no sabe qué cambió y no le importa. Tira todo lo que había en pantalla y lo reconstruye desde cero leyendo el array. Suena ineficiente, pero para listas de este tamaño es instantáneo y hace que el código sea muchísimo más fácil de entender: nunca hay estados intermedios raros. Es, en esencia, una versión mínima de lo que hace React.

8 · Agregar, completar y borrar

Fijate en el patrón: las tres funciones hacen exactamente lo mismo en el mismo orden. Cambian el array, guardan, y vuelven a dibujar. Nada más.

script.js
function agregarTarea(texto) {
  tareas.unshift({
    id: Date.now(),
    texto: texto,
    hecha: false
  });
  guardarTareas();
  dibujar();
}

function alternarTarea(id) {
  const tarea = tareas.find(t => t.id === id);
  if (!tarea) return;
  tarea.hecha = !tarea.hecha;
  guardarTareas();
  dibujar();
}

function borrarTarea(id) {
  tareas = tareas.filter(t => t.id !== id);
  guardarTareas();
  dibujar();
  mostrarAviso('Tarea eliminada');
}
  • .unshift(...)Agrega al principio del array, para que la tarea nueva aparezca arriba. Si preferís que aparezca abajo, cambiá unshift por push: es literalmente la única diferencia.
  • Date.now()Devuelve los milisegundos transcurridos desde 1970. Es un número distinto cada vez, así que sirve perfecto como identificador único sin instalar ninguna librería.
  • .find(t => t.id === id)Busca el primer elemento que cumpla la condición y lo devuelve. A diferencia de filter, devuelve el objeto solo, no un array.
  • if (!tarea) returnSi no encontró nada, salimos de la función. Sin esta línea, la próxima línea intentaría leer una propiedad de undefined y la app se rompería.
  • tarea.hecha = !tarea.hechaInvierte el valor: si era true pasa a false y viceversa. Un solo renglón para "marcar y desmarcar".
  • tareas = tareas.filter(t => t.id !== id)Para borrar no quitamos un elemento: creamos un array nuevo sin ese elemento y lo reasignamos. Por eso tareas se declaró con let y no con const.
El patrón que se repite

cambiar el array → guardar → dibujar. Siempre en ese orden, siempre las tres. Si más adelante agregás una función nueva (por ejemplo, "editar tarea"), seguí este mismo patrón y va a funcionar sin que tengas que tocar nada más.

9 · Escuchar al usuario

El formulario

script.js
formulario.addEventListener('submit', evento => {
  evento.preventDefault();
  const texto = entrada.value.trim();
  if (texto === '') {
    mostrarAviso('Escribí algo primero');
    return;
  }
  agregarTarea(texto);
  entrada.value = '';
  entrada.focus();
});
  • addEventListener('submit', ...)"Cuando este formulario se envíe, ejecutá esta función". Se dispara tanto al hacer clic en el botón como al presionar Enter.
  • evento.preventDefault()Fundamental. Por defecto, enviar un formulario recarga la página entera y perderías todo. Esto lo cancela.
  • .trim()Saca los espacios del principio y del final. Sin esto, alguien podría agregar una tarea que es solo espacios en blanco.
  • entrada.value = ''Vacía el campo después de agregar, para que se pueda escribir la siguiente sin borrar a mano.
  • entrada.focus()Vuelve a poner el cursor en el campo. Permite agregar diez tareas seguidas sin tocar el mouse. Detalles así son los que hacen que una app se sienta bien hecha.

Delegación de eventos: la técnica clave

script.js
lista.addEventListener('click', evento => {
  const boton = evento.target.closest('[data-accion]');
  if (!boton) return;

  const id = Number(boton.closest('.tarea').dataset.id);

  if (boton.dataset.accion === 'alternar') alternarTarea(id);
  if (boton.dataset.accion === 'borrar')   borrarTarea(id);
});

Acá hay una idea que vale oro. En vez de ponerle un escuchador de clics a cada botón de cada tarea, le ponemos uno solo a la lista completa. Cuando hacés clic en un botón, el evento "sube" desde el botón hasta la lista, y ahí lo atrapamos.

  • evento.targetEl elemento exacto donde se hizo clic. Puede ser el botón, o el ícono que está adentro del botón.
  • .closest('[data-accion]')Sube por los elementos padres hasta encontrar uno que tenga el atributo data-accion. Así funciona igual hagas clic en el botón o en el dibujito de adentro.
  • if (!boton) returnSi el clic fue en un espacio vacío de la lista, no hay nada que hacer.
  • .dataset.idLee el atributo data-id que habíamos escrito al dibujar. data-mi-cosa se lee como dataset.miCosa.
  • Number(...)Los atributos HTML siempre son texto. Como los id son números, hay que convertirlos: si no, "123" === 123 daría falso y find nunca encontraría la tarea.
Por qué esto importa tanto

Con delegación, el código funciona para tareas que todavía no existen. Si le pusieras un escuchador a cada botón al dibujar, tendrías que volver a asignarlos cada vez que se redibuja la lista, y cada uno consumiría memoria. Con 500 tareas, eso son 1.000 escuchadores contra 1. Esta técnica se usa en prácticamente todas las aplicaciones web serias.

Los filtros

script.js
filtros.addEventListener('click', evento => {
  const boton = evento.target.closest('[data-filtro]');
  if (!boton) return;

  filtroActual = boton.dataset.filtro;

  filtros.querySelectorAll('.filtros__boton')
         .forEach(b => b.classList.remove('filtros__boton--activo'));
  boton.classList.add('filtros__boton--activo');

  dibujar();
});
  • querySelectorAll(...)Devuelve todos los elementos que coinciden, no solo el primero.
  • .forEach(b => ...)Recorre esa colección y ejecuta algo con cada uno. Acá: sacarle la clase de "activo" a todos.
  • boton.classList.add(...)Y después se la ponemos solo al que se acaba de clickear. Apagar todos y prender uno: el patrón clásico de pestañas.

Glosario de bolsillo

  • arrayUna lista ordenada de valores: [1, 2, 3].
  • objetoUn conjunto de datos con nombre: { nombre: "Ana", edad: 30 }.
  • mapTransforma cada elemento y devuelve un array del mismo tamaño.
  • filterDevuelve un array más chico, solo con los que cumplen una condición.
  • findDevuelve el primer elemento que cumple la condición (no un array).
  • someDevuelve true si al menos uno cumple la condición.
  • estadoLos datos que describen la app en este momento. Acá: tareas y filtroActual.
  • eventoAlgo que pasa en la página: un clic, una tecla, el envío de un formulario.
  • DOMLa representación de la página que el navegador tiene en memoria y que JavaScript puede modificar.
  • delegaciónEscuchar eventos en un elemento padre en lugar de en cada hijo.
  • persistenciaQue los datos sobrevivan al cerrar la página.
